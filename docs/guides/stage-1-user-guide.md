# Гайд пользователя: Стадия 1 (исследование, без реальных денег)

На этой стадии Ballast только **наблюдает и считает**: собирает публичные данные, считает чистую доходность, ведёт виртуальный портфель на 10 000 $ и в конце пишет отчёт «стоит ли идти дальше» (Go/No-Go).

✅ **Кошельки, приватные ключи и ключи бирж на этой стадии НЕ нужны.** Деньги никуда не переводятся.

От вас нужно четыре вещи: бесплатный RPC-ключ, Telegram-бот, настроенный `.env` и установленные инструменты. Шаги 1–5 займут примерно 30–40 минут.

---

## Шаг 1. Бесплатный RPC-ключ Alchemy

RPC (точка доступа к блокчейну) нужна, чтобы программа читала данные из сетей Arbitrum и Base и делала их локальную копию для проверки сделок.

- [ ] 1.1. Зайдите на https://www.alchemy.com и зарегистрируйтесь (бесплатный тариф **Free**, банковская карта не нужна).
- [ ] 1.2. Создайте приложение (**Create new app**), назовите его, например, `ballast`.
- [ ] 1.3. В списке сетей включите **Arbitrum Mainnet** и **Base Mainnet**.
- [ ] 1.4. Откройте приложение и скопируйте **API Key** (строка из букв и цифр).
- [ ] 1.5. Сохраните ключ пока у себя. В шаге 3 мы вставим его в `.env`.

⚠️ RPC-ключ не даёт доступа к деньгам, но всё равно не публикуйте его: чужие люди смогут израсходовать ваш бесплатный лимит.

## Шаг 2. Telegram-бот для уведомлений

Бот будет присылать вам находки, дневные и недельные итоги, предупреждения о рисках.

- [ ] 2.1. Откройте в Telegram бота **@BotFather** (у официального синяя галочка).
- [ ] 2.2. Отправьте ему `/newbot`, задайте имя (например, `Ballast Monitor`) и юзернейм, который заканчивается на `bot` (например, `my_ballast_monitor_bot`).
- [ ] 2.3. BotFather пришлёт **токен** вида `123456789:AAH...`. Это `TELEGRAM_BOT_TOKEN`.
- [ ] 2.4. Найдите своего нового бота в поиске Telegram и нажмите **Start** (или отправьте ему любое сообщение). Без этого бот не сможет вам писать.
- [ ] 2.5. Узнайте свой `TELEGRAM_CHAT_ID`: откройте в браузере
  `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates`
  (вместо `<ВАШ_ТОКЕН>` вставьте токен без угловых скобок). В ответе найдите `"chat":{"id":123456789,...}`. Это число и есть `TELEGRAM_CHAT_ID`.
  Если ответ пустой (`"result":[]`), отправьте боту ещё одно сообщение и обновите страницу.

⚠️ Токен бота даёт полный контроль над ботом. Не показывайте его никому и не выкладывайте в чаты и скриншоты.

## Шаг 3. Файл настроек `.env`

`.env` хранит ваши личные настройки и ключи. Он **никогда** не попадает в git (это уже настроено).

- [ ] 3.1. В папке проекта выполните:
  ```bash
  cp .env.example .env
  ```
- [ ] 3.2. Откройте `.env` в редакторе и заполните:
  - `RPC_URL_ARBITRUM=https://arb-mainnet.g.alchemy.com/v2/ВАШ_КЛЮЧ_ALCHEMY`
  - `RPC_URL_BASE=https://base-mainnet.g.alchemy.com/v2/ВАШ_КЛЮЧ_ALCHEMY`
  - `TELEGRAM_BOT_TOKEN=токен из шага 2.3`
  - `TELEGRAM_CHAT_ID=число из шага 2.5`
  - `DB_PASSWORD=` придумайте любой пароль (он нужен только для локальной базы данных на вашем компьютере)
- [ ] 3.3. Остальные значения оставьте как есть. Это согласованные лимиты из [docs/decisions.md](../decisions.md).
- [ ] 3.4. Проверьте, что git не видит файл: команда `git status` **не должна** показывать `.env`.

## Шаг 4. Установка инструментов

Вы работаете в WSL2 (Linux внутри Windows). Все команды ниже выполняются в терминале WSL.

### 4.1. Docker
Docker запускает базу данных и все части программы в изолированных «контейнерах», чтобы ничего не ставить в систему вручную.

- [ ] Проверьте, что Docker работает:
  ```bash
  docker --version
  docker compose version
  docker run --rm hello-world
  ```
  Если последняя команда напечатала `Hello from Docker!`, всё в порядке.
  Если ошибка доступа (`permission denied`), выполните `sudo usermod -aG docker $USER`, закройте терминал и откройте снова.
  Если Docker не запущен: запустите **Docker Desktop** в Windows и проверьте, что в настройках включено **Settings → Resources → WSL integration** для вашего дистрибутива.

### 4.2. uv (менеджер Python-пакетов)
У вас он уже установлен. Проверка:
- [ ] `uv --version`

### 4.3. Foundry (Anvil)
Anvil делает локальную копию («форк») сети Arbitrum или Base прямо на вашем компьютере. На ней программа «понарошку» выполняет сделки и проверяет, что расчёт совпадает с реальностью. Настоящие деньги при этом не участвуют.

- [ ] Установите:
  ```bash
  curl -L https://foundry.paradigm.xyz | bash
  ```
- [ ] Закройте и снова откройте терминал (или выполните `source ~/.bashrc`), затем:
  ```bash
  foundryup
  anvil --version
  ```
  Должна появиться версия, например `anvil 1.x.x`.
- [ ] Если пишет `foundryup: command not found` (установщик не всегда сам добавляет папку в PATH, то есть в список мест, где терминал ищет программы):
  ```bash
  echo 'export PATH="$PATH:$HOME/.foundry/bin"' >> ~/.bashrc
  source ~/.bashrc
  anvil --version
  ```

⚠️ Ставьте Foundry только с официального адреса `foundry.paradigm.xyz`.

## Шаг 6. Запуск (после того как код Стадии 1 будет готов)

Эти команды заработают по ходу Стадии 1. Я напишу, когда каждая из них станет доступна.

| Что сделать | Команда | Что происходит |
|---|---|---|
| Запустить всё | `make up` (то же, что `docker compose -f docker-compose.local.yml up -d`) | Поднимаются база данных, очередь задач, сборщик данных, аналитика, Telegram-бот |
| Проверить, что всё живо | `docker compose -f docker-compose.local.yml ps` | У всех сервисов статус `healthy` |
| Разовое сканирование | `make scan` | Сбор свежих данных и список возможностей с расчётом чистой доходности |
| Бэктест на закрытых рынках | `make backtest` | Проверка на рынках, которые уже погасились: что бы получилось |
| Проверка сделок на форке | `make simulate` | «Понарошку» выполняет вход и выход на копии сети и сравнивает с расчётом |
| Отчёт | `make report` | Собирает текущие метрики для отчёта Go/No-Go |
| Остановить | `make down` | Всё останавливается, данные в базе сохраняются |

Сбор данных должен идти **минимум 4 недели**. Компьютер в это время должен быть включён, а Docker запущен (можно оставлять на ночь). Пропуски в данных не страшны: они честно отражаются в отчёте.

## Шаг 7. Как читать отчёт Go/No-Go

Отчёт будет в файле `docs/reports/stage-1-go-no-go.md`. Начните с блока **«Простыми словами»** в начале: там 3–6 предложений, что проверяли и стоит ли вкладывать деньги.

Основные термины:
- **NLY (Net Locked Yield, чистая зафиксированная доходность):** сколько вы получите в процентах годовых, если купите актив сейчас и продержите до даты погашения, **после** всех комиссий, газа и проскальзывания.
- **«Парковка»:** доходность простого депозита стейблкоинов в кредитном протоколе (например, Aave). С ней сравнивается всё остальное: если сложная стратегия не обгоняет «парковку» заметно, она не нужна.
- **Газ:** комиссия сети за транзакцию.
- **Проскальзывание:** насколько цена сдвигается против вас, когда вы покупаете крупную сумму.
- **Tier A / Tier B:** уровни риска актива. A: классические стейблкоины (USDC, USDT, DAI). B: синтетические доллары (USDe), они доходнее, но исторически теряли привязку к доллару.
- **Поправка на инциденты:** сколько доходности «съели» бы реальные исторические обвалы и взломы. Если после неё плюс исчезает, риск не окупается.

Критерии успеха (все согласованы с вами):
- чистый доход **не ниже 0,5% в месяц** на данных, по которым пороги не подбирались (обязательно);
- обгон «парковки» минимум на 3 процентных пункта годовых;
- в 70% недель удаётся разместить хотя бы 70% капитала;
- газ и проскальзывание съедают не больше 15% валового дохода;
- проверка на форке совпадает с расчётом с точностью 0,3%;
- на один протокол не больше 35%, на Tier B не больше 25%;
- после поправки на инциденты доходность остаётся положительной.

Итог будет одним из трёх: **Go** (идём к реальным деньгам), **Доработать** (1–2 попытки улучшить), **No-Go** (проект остаётся аналитическим инструментом, без реальных денег). Решение принимаете вы, я только честно показываю цифры.
